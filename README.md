# Калькуляторы «Свобода мысли»

Ипотека, рассрочка, ЧПВ, траншевая ипотека и общий каталог инструментов для ДА1, ДА2 и ДНК-2. Сайт: https://evgeniigusv.github.io/ipoteka-calc/. Ссылки `?theme=light` и `?theme=dark` открывают светлый и тёмный режимы. Переключатель находится в шапке каждого раздела. Для обеих тем использован дизайн партнёрской памятки «Инструменты продаж» и фотографии тех же проектов.

## Данные и личный редактор

Инструменты, совместимость акций, лимиты компенсации и специальные условия квартир хранятся в SQLite **вне репозитория**. Основной каталог — `~/.local/share/ipoteka-calc/catalog.sqlite`; путь можно изменить приватной настройкой `catalog_path`. Google больше не является источником общего каталога. Единственное исключение — банковские ставки и комиссии из справочников субсидий ДА и ДНК в файлах ЧПВ. Они обновляются каждые три часа. Квартиры и цены обновляются из Macro отдельным заданием.

`assets/tools.json` — публичный снимок без записей владельца. Все калькуляторы читают его через `tools-loader.js`. После изменения каталога открытый калькулятор нужно перезагрузить. Схема и проверки данных — `assets/tools-model.js`.

Кнопки на вкладке «Инструменты» открывают редактор в том же окне. Личный сервер на Маке владельца: `http://127.0.0.1:8795/tools.html`. Браузер может запросить доступ к локальной сети. Отдельной системы пользователей пока нет; права GitHub не дают доступ к личному редактору.

- Выберите проект и раздел. Рядом с инструментом — «Редактировать», в пустой ячейке другого проекта — «Добавить».
- В форме видны основные поля. Обязательные отмечены `*`, остальные находятся в «Дополнительно». Название расчётной программы можно оставить пустым.
- «В черновик» сохраняет правку на экране. «Сохранить и опубликовать» записывает пакет в базу и обновляет публичный снимок. Если публикация не завершилась, сохранённые данные остаются в базе; публикацию можно повторить.
- «В архив» выключает инструмент без удаления; архив доступен для восстановления. При создании можно выбрать «Партнёрам» или «Только мне». Закрытые записи не попадают на сайт и в партнёрский PDF.
- У импортируемой ипотеки совместимость, название и доступность сохраняются в приложении, ставки продолжают обновляться. Ручное изменение банковских параметров переводит конкретную карточку под управление приложения.
- В «Инструментах» откройте «Квартиры» и выберите ДА1, ДА2 или ДНК-2. Появятся квартиры выбранного проекта из Macro в статусах «Подбор», «Бронь» и «Маркетинговый резерв». Поиск работает по номеру. В режиме редактирования можно отметить специальные условия квартиры, которые калькуляторы покажут при выборе.
- В разделе «Дополнительные условия» задаются лимит компенсации ипотечной субсидии и стоимость денег для ЧПВ по каждому проекту.
- В рассрочке первоначальный взнос вводится в рублях или процентах от цены по прайсу. При изменении цены сохраняется последнее введённое значение, второе поле пересчитывается; переключателей с готовыми процентами нет.
- Версия каталога проверяется транзакцией SQLite. Конкурирующая запись отклоняется с просьбой перечитать данные; повтор подтверждённого запроса не создаёт дубликаты.

ИИ принимает вставленный текст, диктовку или локальный файл TXT, Markdown, DOCX, PDF с текстовым слоем. Материал отправляется в OpenAI. Предложения показываются до применения, допускают ручную правку и пакетное принятие. При неоднозначных числах или единицах требуется уточнение. Протоколы из Google не загружаются.

## Правила расчётов

- **Ипотека:** кредит равен цене ДДУ минус ПВ. Комиссия считается от окончательного кредита. При включённой компенсации компания покрывает фактическую комиссию в пределах лимита от акционной цены. Лимит задаётся в настройках (при переносе — 10%). Остаток комиссии увеличивает цену и кредит; зависимость решается аналитически: `ДДУ = акционная цена + max(0, (комиссия × (акционная цена − ПВ) − лимит в рублях) / (1 − комиссия))`. Неиспользованная компенсация не даёт дополнительной скидки.
- **Рассрочка:** скидка применяется ко всей цене или только к ПВ, в зависимости от галочки инструмента. При ПВ от 71% действует актуальная скидка полной оплаты вместо обычной скидки рассрочки. В интерфейсе скидка округлена до целого процента, расчёт сохраняет точность. Старые потолки, стартовая скидка рассрочки, варианты ПВ и скидка при 70% не используются.
- Для равных платежей администратор разрешает периоды 1, 2, 3, 6, 12 месяцев. У схемы «Взнос и остаток» промежуточных платежей нет. Этапы задаются датами и суммами; прежние этапы с долями и относительными месяцами поддерживаются. Скрытые параметры другой схемы не участвуют в расчёте.
- Дата погашения должна быть впереди; срок в месяцах отсчитывается от сделки. Прошедшая дата оформления программы даёт примечание, но не подменяет дату погашения.
- **Акции:** каждому инструменту назначаются совместимые акции по их ID. По умолчанию скидки суммируются, альтернативный режим — последовательное применение. Процентную акцию можно добавить как запись раздела «Скидки и акции» с полем процента. Информационные условия без числового параметра показываются как условия акции и сами цену не меняют. Основная скидка полной оплаты учитывается отдельно, повторно не добавляется. При переносе текстовые сочетания сопоставляются с ID только при однозначном совпадении; прежний текст остаётся в редакторе для сверки, остальные сочетания нужно выбрать галочками.
- **Транши:** платёж от накопленной выданной суммы на выбранный срок. ДА поддерживает расчёт по ставке и предварительно по ориентиру платежа. Первый транш 100 000 ₽ в программе с таким условием, второй — остаток. Расчёт не заменяет банковский график погашения основного долга.
- **ЧПВ:** «Стоимость денег» задаётся в «Дополнительных условиях» проекта и применяется ко всем его программам ЧПВ. Сохраняются формулы финансирования ПВ и сверхлимита.
- Все PDF содержат дисклеймер: «Не является публичной офертой. Окончательные расчёты уточнять у менеджера отдела продаж.» Он располагается внизу страницы с отдельным полем. В браузерах без поддержки полей печатной страницы при обычной печати текст выводится в конце документа.

## Запуск и API

`python3 automation/tools_editor.py`; установка автозапуска macOS — `python3 automation/install_tools_editor.py`. Журнал: `~/Library/Logs/ipoteka-tools-editor.log`. Приватный конфиг: `~/.config/ipoteka-calc/tools.json`, права 0600. Ключ OpenAI хранится вне Git; настройка `openai_env` задаёт путь к защищённому файлу. Источники субсидий для Mac — `~/.config/ipoteka-calc/sheets.json`, для GitHub — секрет `SUBSIDY_SOURCES`.

`GET /api/session` создаёт сессию и выдаёт CSRF. Чтение — `GET /api/tools`, `GET /api/settings`. Запись инструментов — `POST /api/events/tools-changed` с `{revision, changes:[полные записи]}`, предварительная проверка — дополнительно `preview:true`. Запись настроек — `POST /api/settings` с `{revision, settings}`. Повтор публикации — `POST /api/publish` с `{}`. Запросы требуют сессию и CSRF; авторизация действует только на локальном сервере. Проценты в JSON — доли, деньги — целые рубли. Публикуемые данные проверяются общей схемой.

GitHub Actions `weekly-installments.yml` теперь обновляет **только банковские ставки** каждые три часа; название файла сохранено для истории. `sync_tools.py --mortgage-only` не читает общие таблицы инструментов. `automation/sync_macro.py` обслуживает отдельное задание `ru.svobodamysli.ipoteka-macro`; журнал `~/Library/Logs/ipoteka-macro.log`. ПИФ исключён из выбора квартир в калькуляторах.

## Резервные копии и восстановление

Перед переносом сохраняются исходные публичные и закрытые записи, проверяется повторное чтение, затем создаётся SQLite и проверяется её восстановление. Исходный архив и отчёт о переносе хранятся вне Git. `owner_catalog.py --migrate-google <папка>` — **одноразовая** административная операция, повтор поверх существующей базы запрещён. Для обычной работы Google OAuth не нужен.

`python3 automation/owner_catalog.py --backup` создаёт проверенные копии SQLite в `backup_dir` (по умолчанию `~/Backups/ipoteka-calc/catalog`) и отдельно в обязательной `external_backup_dir`. Резервирование выполняется также сервером после изменений и при фоновом обновлении. Базы и закрытые исходные выгрузки не публикуются в GitHub.

Восстановление:

1. Остановить личный редактор и сохранить текущую базу отдельно.
2. Вызвать `owner_catalog.restore_backup(путь_копии, новый_путь)` из Python с `automation` в пути модулей. Функция проверяет целостность SQLite, схему и настройки; существующий файл не перезаписывает.
3. Указать восстановленный файл в приватном `catalog_path`, запустить редактор, проверить инструменты и настройки, затем опубликовать снимок.
4. Для другого Mac восстановить приватный конфиг и ключи из защищённой копии; установить Python 3.9+, Node.js, curl и авторизовать `gh`. Код восстановить из GitHub, базу — из резервной копии.

GitHub содержит сайт и историю публичных снимков. Для восстановления сайта включить Pages из `main`, корня репозитория. Прежняя служба `ru.svobodamysli.ipoteka-mortgage` отключена; не включать её параллельно новой синхронизации.

## Проверки

`node --test tests/*.test.mjs` и `python3 -m unittest discover -s tests -p '*_test.py'`. Тест Macro требует PyMySQL (на этом Mac он есть в `~/code/agent-sales-bi/.venv`). Сетевые источники и ИИ в тестах заменены фикстурами. Исторические фикстуры сохраняют старые условия для сравнения. Локальный просмотр без редактирования: `python3 -m http.server 8796`.
